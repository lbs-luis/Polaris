Conversation Summary for Polaris Mobile App Development
Project Overview
- App Name: Polaris ("It guides you to where your 'forward' is")
- Type: React Native mobile app using Expo SDK ~54
- Core Features: 
  1. Simple expense management with categories
  2. Shopping list system that converts to expenses
  3. Monthly income confirmation workflow
  4. Completely offline with local Android storage
- Architecture: Simplified for solo open-source development
- Database: WatermelonDB with SQLite backend
What We've Accomplished
1. Architecture Design (Completed)
- Simplified folder structure: src/database/, src/screens/, src/components/, src/services/, src/types/, src/utils/
- Integration-first testing approach: Focus on component + database integration tests over unit tests
- Direct database usage: No repository pattern, components query WatermelonDB directly
2. Database Schema Design (Completed)
// Tables designed:
- shopping_lists (title, status, total_price, timestamps)
- list_items (name, price, purchased, list_id, timestamp)  
- categories (name, type: 'expense'|'income', timestamp)
- transactions (title, amount, date, category_id, timestamp)
- income_records (title, expected_value, actual_value, date, confirmed, month_year, timestamps)
- monthly_summaries (month_year, total_income, total_expenses, net_balance, category_breakdown)
- yearly_summaries (year, total_income, total_expenses, total_saved, top_category)
3. Testing Strategy (Completed)
- Test Pyramid: E2E (1 Maestro test) → Integration (most) → Unit (essential only)
- Tools: Jest + React Native Testing Library for integration tests
- E2E Test: Critical user journey (onboarding → list creation → expense confirmation)
- TDD Workflow: Integration-first development cycle
4. Historical Data & Analytics Strategy (Completed)
- Invoice History: Confirmed safe to keep (< 10MB for 5+ years)
- Income Tracking: Monthly confirmation workflow with early warnings
- Lightweight Analytics: Summary tables for instant year-over-year comparisons
- Optimization: Data archival, smart indexing, lazy loading

Key Technical Decisions Made
- WatermelonDB over Prisma: Better React Native support, reactive queries
- Summary tables for analytics: 97% data reduction vs raw queries
- Monthly income confirmation: User confirms actual income each month
- Historical data retention: Safe to keep completed lists as history
- Integration-first testing: Higher accuracy, better for solo development
Database Size Confidence
- Estimated 5-year usage: ~2.5MB total
- Performance impact: Minimal with proper indexing
- Storage concerns: None - well within mobile device limits
